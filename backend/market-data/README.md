# market-data

Downloads historical OHLCV data, validates it, persists it to PostgreSQL, and
exposes it over a REST API. This is the AQROS Phase 1 slice of the eventual
Market Data Service described in `docs/AI_QUANT_PLATFORM_BLUEPRINT.md` §3.2 —
scoped to historical equities data only (no live feeds, no Kafka publishing,
no security-master/crosswalk; those are later phases).

## Architecture (ports-and-adapters)

- `domain/` — pure business logic, no I/O: `models.py` (Instrument, OHLCVBar),
  `validation.py` (business + point-in-time rules), `ports.py`
  (`MarketDataProvider`, `BarRepository`, `InstrumentRepository` interfaces),
  `services.py` (ingestion + query orchestration over those ports).
- `adapters/` — concrete I/O: `db.py` + `orm.py` (SQLAlchemy 2.0 async engine
  and models), `repository.py` (Postgres-backed repositories), plus
  `providers/yfinance_provider.py` — the only provider in Phase 1. Adding
  Alpaca/Polygon/TwelveData later means adding a sibling module here that
  implements `MarketDataProvider`; nothing in `domain/` or `api/` changes.
- `api/` — FastAPI routes (`routes/ingestion.py`, `routes/market_data.py`),
  Pydantic schemas (`schemas.py`), and DI wiring (`deps.py`).
- `migrations/` — Alembic migrations (`instruments`, `ohlcv_bars` tables).

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/v1/ingestion` | Download historical OHLCV for a symbol/date range and persist validated bars |
| `GET` | `/v1/instruments` | List known instruments |
| `GET` | `/v1/instruments/{symbol}` | Fetch one instrument |
| `GET` | `/v1/instruments/{symbol}/bars` | Retrieve stored OHLCV bars (filterable by date range, paginated) |
| `GET` | `/health`, `/health/live`, `/health/ready` | Health probes (readiness includes a live DB check) |
| `GET` | `/docs`, `/openapi.json` | OpenAPI docs (auto-generated by FastAPI) |

## Running locally

Via Docker Compose (recommended — brings up Postgres too):

```bash
docker compose up -d market-data-db market-data
# run the migration once the DB is healthy:
docker exec -w /app/backend/market-data <container> python -m alembic upgrade head
curl localhost:8002/health/ready
```

Directly (needs a reachable Postgres — see `AQROS_DATABASE_URL` below):

```bash
uv run --directory backend/market-data alembic upgrade head
uv run python -m aqros_market_data.main   # listens on port 8002
```

## Configuration (env vars, prefix `AQROS_`)

| Variable | Default | Purpose |
|---|---|---|
| `AQROS_DATABASE_URL` | `postgresql+asyncpg://aqros:aqros@localhost:5432/aqros_market_data` | Async SQLAlchemy DSN |
| `AQROS_MARKET_DATA_PROVIDER` | `yfinance` | Selects the `MarketDataProvider` implementation |
| `AQROS_DB_POOL_SIZE` / `AQROS_DB_MAX_OVERFLOW` | `5` / `10` | Connection pool sizing |
| `AQROS_INGESTION_REQUEST_TIMEOUT_SECONDS` | `30.0` | Per-request timeout to the provider |
| `AQROS_INGESTION_MAX_RETRIES` | `3` | Retry attempts on provider failure |

See root `.env.example` for the full list shared with other services.

## Tests

- `tests/unit/` — pure domain logic (validation, ingestion orchestration
  against fakes). No I/O, run on every commit.
- `tests/integration/` — real Postgres via testcontainers (repository
  behavior, the full API through `httpx.AsyncClient`, and an Alembic
  `upgrade head` schema check). Requires Docker; marked `integration`.

```bash
uv run pytest backend/market-data                      # unit + integration
uv run pytest backend/market-data -m "not integration"  # unit only, no Docker
```
